# 0050: 既存の ADR を今の書式へ一度だけ揃える

- Date: 2026-11-18
- Status: Accepted
- Amends: 0022

## 背景

ADR の書式は、背景、決定、検討した代替案、影響の 4 つの節と `Date` を持つ形に決まった（`dot_claude/skills/scribe/references/adr-format.md`）。既存の 49 件は、英語の見出し（Context / Decision / Consequences）、見出しの無い短い形、今の書式が混ざり、`Date` はどれにも無い。ADR 0022 は、既存の ADR の本文を書き換えず、直接直すのは状態と関係のメタデータと、判断の内容を変えない修正に限ると定めている。

## 決定

0001 から 0049 を、一度だけ今の書式へ揃える（2026-11-18 のユーザー判断）。

- 本文の文を 4 つの節へ並べ替え、見出しを日本語にする。判断の内容と理由は変えず、文を新しく足さない。
- 元の本文に無い節は、推測で埋めずに「記録に残っていない。」と書く。
- `Date` は、その ADR のファイルを最初に追加した commit の日付（git の author date）にする。
- これは一度だけの例外で、ADR 0022 の規則はこの後も有効。これから作る ADR の本文は書き換えない。

## 検討した代替案

- そのまま残す: 書式が 3 通り混ざったままになり、読み手は ADR ごとに節の場所を探すことになる。
- `Date` だけを足す: 日付は揃うが、代替案と影響の場所は ADR ごとに違うまま残る。

## 影響

- 49 件が同じ節の並びになり、どの ADR でも同じ位置で背景、決定、代替案、影響を読める。
- 0001 から 0049 の本文は、採用時点の形ではなくなる。採用時点の形は git の履歴にある。
- 並べ替えで文が失われていないことは、元の本文の文を全部、直した後の本文から探して確かめた。
