# Privacy

commit、doc、設定、その他の成果物に、書き手と作業機を特定する値を残さない。

対象は個人と環境の識別子であって、credential や token ではない。秘密情報の扱いは `~/.claude/CLAUDE.md` の停止線が持つ。

## 残さない値

- home の絶対パス。`/Users/<name>`、`/home/<name>`、`C:\Users\<name>`
- OS のログインユーザー名、ホスト名、機器名
- 個人のメールアドレス。git の author には公開用のアドレスを使う（GitHub なら noreply）
- 実名、個人アカウントの旧 ID、個人を特定する URL
- 組織内のホスト名、内部 IP、社内固有の識別子

## 代わりに書くもの

- home 起点のパスは `~/` または `$HOME`。doc の地の文では `/Users/<user>` のようなプレースホルダ
- repo 内のファイルから同じ repo を指す時は相対パス。絶対パスを書かない
- 例示は合成値。`user@example.com`、`/home/user`、`example.com`

## 混入しやすい場所

**別の場所から定型部を引き写した時。** scratchpad、他 repo、過去の版から header やテンプレートをそのまま持ってくると、元の環境の値が一緒に入る。引き写したら、その値が今の置き場でも通用するか見る。

エラーメッセージやコマンド出力を doc へ貼る時も同じ。実行環境のパスがそのまま残る。

public repo では、一度 push した値は force push しても直ちには消えない。commit する前に見る。

## この rule 自身に値を書かない

検出したい文字列を rule や設定ファイルへ直書きすると、その rule 自体が値を持ち、配布先すべてに広がる。パターンで書く。
