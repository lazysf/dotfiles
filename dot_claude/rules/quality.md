# Quality

## 品質の優先順位

正しさ・安全性 → 人による可読性・修正容易性 → 既存規約・近傍実装との一貫性 → 必要な性能 → DRY。
上位を損なう下位適用はしない。短さと巧妙さは目標にしない。可読性の結果として短くなるのはよい。

## 適用の参照順

リポジトリの明示規約 → 近傍実装 → 依頼を満たす最小差分 → 基本原則。

## 基本原則

- **可読性**: 未来の修正者が少ない文脈で誤解せず安全に変えられる形。
- **KISS**: 単純で検証しやすい案。失敗境界では何が失敗したか追える形を残す。
- **YAGNI**: 未確定の将来要件を先回りしない。
- **DRY**: 実害のある重複だけ解消する。意味や変更理由が違う重複は残す。

## 最小差分（surgical changes）

- 隣接コード・コメント・整形を「ついで改善」しない。既存スタイルが自分の好みと違っても合わせる。
- 無関係な dead code や問題に気づいたら、修正せず言及に留める。
- 自分の変更で未使用になった import / 変数 / 関数は消す。元から在る未使用は依頼がない限り消さない。
- 判定テスト: 全ての変更行が依頼にトレースできるか。
