# コーディングガイドライン

`src/**` の実装における基本原則は [coding-standards rule](../../../rules/coding-standards.md) を正本とする。

ここでは、その原則を実装中に適用する時の進め方を補う。

## 進め方

- 先にテスト、再現手順、比較観点のいずれかを置く。
- 最初は依頼を満たす最小で直線的な差分に留める。
- 命名、責務、エラー処理、テスト配置は近傍実装と明示規約に寄せる。
- 動作確認後、読みやすさ、変更容易性、検証容易性が明確に改善する整理だけ行う。

## 迷う時の判断

- 抽象化、分割、helper 化、新規依存追加が必要に見える場合は、理由、影響範囲、より単純な代替案を先に確認する。
- コメントは、見れば分かる処理ではなく、制約や意図がないと読み取りにくい箇所にだけ置く。
- 失敗しうる境界では、何が失敗したか後から追える形を残す。

## 仕上げ

- 今回の依頼を満たす差分に留まっているか確認する。
- 実行できた確認と未検証事項を分けて説明できる状態にする。
