# Scribe

## 3 層の使い分け

| 層 | 中身 | 置き場 |
| --- | --- | --- |
| 仕様・使い方 | 何を・どう使うか | `README.md` / `docs/` |
| ADR | なぜそうしたか | `docs/adr/` |
| notes | 背景・調査・現在の設計の理由 | `docs/notes/` |

**doc は実装が固まった後に、確認済みの事実から作る。** 事前に書いて実装を駆動しない。

## notes は現在の設計を書く

notes に**変更履歴を書かない**。「旧規定は〜だった」「〜に直した」ではなく、「現在こうなっている。理由は〜」と書く。過去の状態は git 履歴にある。

例外は、同じ失敗を繰り返さないために必要な事実。「この設定を入れると別の機構が壊れる」「この方法は試して効かなかった」は、現在の設計の理由として書く。

**判断記録（複数案を比較した結果）は notes ではなく ADR に書く。** ADR の 3 条件を満たさない判断は notes でよいが、その場合も「なぜ今この形か」として書き、検討の経緯を並べない。

## ADR を作る条件

3 条件を**全部**満たす時だけ作る。

1. **複数案を実比較した**: 仮想でなく実在する代替案を検討した。
2. **覆すコストが高い**: 公開 IF / データ形式 / 永続化 / 認証 / 依存に関わり、後で方向転換すると痛い。
3. **捨てた案に再検討の価値がある**: 将来の読み手が「なぜ A でなく B か」を疑問に思う。

戻しやすい判断、明らかな判断、実質的な代替案がない判断では作らない。3 条件を満たさないのに ADR を求められたら、不要と明示するか notes を提案する。

## 既存 ADR の扱い

**本文は採用時点の履歴として保持する。** 方針変更、判断の補正、理由や影響の再解釈は、本文を書き換えず新しい ADR として記録する。

直接編集してよいのは次の 2 つだけ。

- `Status`、`Superseded-By`、`Amended-By` などの状態・関係メタデータ
- typo、**リンク切れ**、Markdown の破損など、判断内容を変えない修正

`Supersedes` / `Superseded-By` / `Amends` / `Amended-By` を推測で書かない。ユーザー依頼か会話上の合意で確認できたものだけ使う。

前提を失った ADR が複数ある時の退役手順は [references/adr-format.md](references/adr-format.md) にある。

## 共通の進め方

- 根拠となる一次情報（コード、差分、コマンド結果、確定済みの合意）を特定する。
- 既存の自然な位置に差し込む。新規 doc は既存に収まらない時だけ作る。
- 既存の章構成、用語、粒度、文体に寄せ、最小差分に留める。1 つの概念に 1 つの語を使い、doc の途中で言い換えない。
- 未確認のことは「未確認」として分けるか、書かない。
- 追加・削除・rename した doc は、README / 索引 / 相対リンクの追従を確認する。解消しないリンク切れは、所在と理由を残す。

## 書式

書き始める前に、対象の reference を 1 つだけ読む。記憶や推測で書かない。

- README / docs: [references/readme-format.md](references/readme-format.md)
- ADR: [references/adr-format.md](references/adr-format.md)
- notes: [references/notes-format.md](references/notes-format.md)

## Gotchas

- **ADR には確定した判断だけを書く。** 「この部分はまだ実行していない」「次はこうする予定」を書くと、実行されなかった時に ADR が嘘になる。予定に言及したくなったら、その ADR にその話は要らない。
- **既存 doc に規定を足す前に、既存の実態を数える。** あるべき形を先に決めてから既存を見ると、大多数と食い違う規定ができる。`grep -c` や `ls` で現状を数えた上で、実態に合わせるか、意図して外して既存を直すかを選ぶ。

## 扱わないもの

- 開発を駆動する事前 doc（requirements / design / tasks）。
- commit message。`git-commit` skill が扱う。
- 実装や設定で確認できない内容を事実として書くこと。一次情報がなければ書かない。
- 秘密情報、認証情報、private config、本番設定、未公開の個人情報。必要なら停止する。

小さな変更で doc 全体を書き直さない。

## 出力

| 項目 | 内容 |
| --- | --- |
| `artifact_type` | README / ADR / notes |
| `updated_docs` | 作成・更新した path |
| `basis` | 根拠にした一次情報 |
| `open_questions` | 未確認のまま残したこと |

doc が不要と判断した場合も、その旨と理由を返す。
