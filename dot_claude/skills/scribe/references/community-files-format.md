# SECURITY / SUPPORT 形式

`SECURITY.md` と `SUPPORT.md` を作成・更新する時に読む。作る条件（窓口を開く repo）は `../SKILL.md` の「置き場の選び方」の表を正本にする。

## 共通

- 窓口（アドレス、フォーム、GitHub の private vulnerability reporting、議論の場）は推測で書かない。repo から読めなければユーザーに聞く。実在しない窓口を書くと、報告が届かない。
- 窓口が決まらない間は、ファイルを作らない。空の雛形は、窓口があるように見せる。
- GitHub は root、`docs/`、`.github/` のどこに置いても認識する。同じファイルを 2 つ置かない。

## `SECURITY.md`

- 書くもの: 報告の窓口、報告に含めてほしい情報、対応する版の範囲。
- 脆弱性を公開の issue や PR に書かないよう案内する。
- 対応する版の範囲と、返答までの目安は、実際にそうしている事実だけを書く。約束できない期限を書かない。

## `SUPPORT.md`

- 書くもの: 使い方の質問をどこでするか、bug の報告をどこに出すか。
- issue のテンプレートがあれば、bug の報告の書き方はそこに任せ、ここでは指すだけにする。
