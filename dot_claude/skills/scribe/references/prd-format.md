# PRD Format

`docs/PRD.md` を作成・更新する時に使う。
project / product change 全体の要求を置く。個別 feature の詳細要件は `docs/REQUIREMENTS.md` へ寄せる。

## 手順

- 概要、課題、目的、成功条件、スコープ、非目的、制約を整理する。
- ぼんやりした依頼では、まず「何が満たされれば成功か」を固める。

## Template

```markdown
# PRD

## 概要

[何を実現したいか。1-3 文。]

## 課題

[ユーザーに見える問題、workflow の痛み、または機会。]

## 目的

- [観測可能な目的。]

## 成功条件

- [満たされたと判断できる観測可能な結果。]

## スコープ

- [今回含める領域、対象、能力。]

## 非目的

- [意図的に扱わないこと。]

## 利用者 / 関係者

- [対象利用者または関係者。]

## 制約

- [互換性、運用、policy、UX、data、rollout などの制約。]

## 未確認事項

- [未確認事項。]
```
