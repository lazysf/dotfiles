# Requirements Format

`docs/REQUIREMENTS.md` を作成・更新する時に使う。
`FR-*` ごとに振る舞いと受入条件を固める。

## 手順

- PRD や会話の要件を `FR-*` 単位で扱える粒度へ整理する。
- 要求事項、受入条件、非目的、前提・制約を分ける。
- 要件が固まったら、基本設計へ進める。

## Rules

- 機能または要件領域は `FR-001`、具体要求は `REQ-001`、受入条件は `AC-001` のような ID で追跡する。

## Template

```markdown
# 要件定義

## FR-001: [機能または要件領域名]

### 背景

[この要件が必要な確認済み背景。]

### 要求事項

- `REQ-001`: [実現したい振る舞い。]

### 受入条件

- `AC-001`: [観測可能な受入条件。]

### 非目的

- [この要件では扱わないこと。]

### 前提・制約

- 前提: [依存する要件、外部条件、既存仕様。]
- 制約: [互換性、運用、policy、UX、data、rollout など。]

### 未確認事項

- [未確認事項。]
```
