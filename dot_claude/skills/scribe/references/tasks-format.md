# Tasks Format

`tasks.md` は実装前のタスク分解の正本。詳細設計を実装可能な作業単位へ分ける。

## Rules

- `TASK-*` は対応する `DD-*` / `AC-*` を含める。
- task ごとに完了条件と確認方法を持たせる。
- task は小さく、実装しやすく、確認しやすい粒度にする。
- 実装結果、日報、作業ログを書かない。

## Template

```markdown
# Tasks

## 実装方針

[詳細設計に沿った実装方針。対応する `DD-*` を含める。]

## 実装タスク

- `TASK-001`: [実装単位、完了条件、確認方法、対応する `DD-*` / `AC-*`。]

## 実装順序

1. [`TASK-001`: 実装順序と依存関係。]

## 変更境界

- [主な変更対象 file / module。未確定なら候補として書く。]

## Scope 外にしたこと

- [今回実装しないこと。]

## リスク

- [失敗しやすい点、既存挙動への影響。]

## 未確認事項

- [未確認事項。]
```
