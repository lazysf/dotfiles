# Test Case Format

`docs/TEST_CASES.md` を作成・更新する時に使う。
要件とタスクに対応する test case と手動確認を置く。設計対応は Traceability Matrix で整理する。

## 手順

- 自動テスト、手動確認、確認不能または費用対効果が低いものを分ける。
- `TC-*` は前提条件、手順、期待結果、対応する `AC-*` / `TASK-*` を持たせる。
- テストコードを作る場合は、既存の配置、命名、実行入口を確認する。
- TDD が難しい対象では、手動確認、比較観点、最小再現 artifact を先に置く。

## Rules

- `FR-*`、`AC-*`、`TASK-*` と対応付ける。該当しないものは `N/A`。
- `TC-*` は 1 つの期待結果を観測できる粒度にする。
- 自動テストできない場合は、手動確認または比較観点として残す。
- テストコード path は確認済みの場合だけ書く。未作成なら `TBD`。

## Template

```markdown
# テストケース

## FR-001: [機能または要件領域名]

### TC-001: [テストケース名]

#### 対応

- `AC-001`
- `TASK-001`

#### 種別

- [automated | manual | exploratory]

#### 前提条件

- [fixture、workbook、data、権限、設定など。]

#### 手順

1. [確認手順。]

#### 期待結果

- [観測可能な期待結果。]

#### テストコード

- `TBD`

#### 未確認事項

- [未確認事項。]
```
