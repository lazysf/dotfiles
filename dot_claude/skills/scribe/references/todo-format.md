# TODO 形式

保留の作業を `TODO.md` などの doc に書く時に読む。保留の作業を doc と issue のどちらに置くかは、repo の運用に従う。issue で管理している repo では、この reference を使わない。

## 置き場

repo が決めた置き場（`AGENTS.md` や `DEVELOPMENT.md` に書かれた先）に書く。決まっていなければ、作る前にユーザーに聞く。issue も使う repo に `TODO.md` を作ると、保留の作業が二重になる。

## 1 項目に書くもの

- 記載日。
- 見つけた時の作業。後で読む人が、何をしていて見つけたかを追える。
- 完了の条件。何を確かめたら閉じてよいかを書く。条件が無いと、後で閉じてよいかを決められない。

既存の TODO が章立て（作業ごと、環境ごと）や項目の形（checkbox、太字の見出し）を持っていれば、それに合わせる。

## 書かないもの

- 調べた結果の詳細。notes に置き、TODO には指し先だけを残す。notes に置けば、項目を閉じた後も今の設計の理由として残る。
- 着手する作業そのもの。今の作業で直すものは TODO に移さない。

## 閉じる時

完了した項目を消すか、`[x]` を付けて残すかは、既存の TODO の形に従う。
