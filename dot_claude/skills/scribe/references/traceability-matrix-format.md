# Traceability Matrix Format

`docs/TRACEABILITY_MATRIX.md` を作成・更新する時に使う。
要件、設計、タスク、テストケース、テストコードの対応を一覧化する。

## 手順

- `FR-*`、`REQ-*`、`AC-*`、`BD-*`、`DD-*`、`TASK-*`、`TC-*`、テストコードの対応を整理する。
- 対応が確認できないものは推測で埋めず、`TBD` または `N/A` と理由を残す。
- 要件に設計、タスク、テストがない場合は漏れとして分ける。
- 設計、タスク、テストが要件に紐付かない場合は孤立として分ける。

## Rules

- 追跡対象がない場合は `N/A` または `TBD` を使い、理由を `備考` に残す。
- `REQ-*` / `BD-*` / `DD-*` / `TC-*` は要件定義・基本設計・詳細設計・テストケースを別建てした時の ID。feature note 1 枚で進めた場合は `AC-*` だけが埋まり、これらの列は `N/A`（feature note に集約）と残す。

## Template

```markdown
# トレーサビリティマトリクス

| 機能 / 要件領域 | 要求事項  | 受入条件 | 基本設計 | 詳細設計 | タスク     | テストケース | テストコード | 状態      | 備考                               |
| --------------- | --------- | -------- | -------- | -------- | ---------- | ------------ | ------------ | --------- | ---------------------------------- |
| `FR-001`        | `REQ-001` | `AC-001` | `BD-001` | `DD-001` | `TASK-001` | `TC-001`     | `TBD`        | `planned` | [未作成、対象外、不明などの理由。] |
```

## 状態

- `draft`: まだ問い詰め中
- `planned`: 実装計画まである
- `implemented`: 実装済み
- `verified`: 確認済み
- `deferred`: 後回し
