# Knowledge Placement Rules

判断基準:

- 個人の作業メモや一時的な調査メモは、チーム共有の docs と混ぜない
- チームやプロジェクトで再利用する知識だけを共有対象にする
- 手順、確認ポイント、落とし穴は通常知見として扱う
- 選択理由や却下した代替案ごと残す判断は ADR として扱う
- 通常知見の文面化には `write-knowledge-note`、ADR 作成には `write-adr` を使う
- 既存 ADR の状態更新や supersede 反映には `update-adr-status` を使う
- すでにコード、コメント、設定、成果物で十分に伝わる内容は追加しない
- docs を追加する場合は既存構造に寄せる
- 置き場が曖昧な場合は、[AGENTS.md](../../../AGENTS.md) の置き場の原則に従う

共有候補になりやすいもの:

- API 変更や互換性の判断
- 運用手順の変更
- 以後も参照する設計判断
- 再発しやすい落とし穴や確認ポイント
- 複数案からの選定理由や採用 / 不採用の決定
