# Change Review

高品質なバイブコーディングのための、出口専用レビュースキル。
目的は、変更後に「何が問題か」「何が未確認か」を短く正確に整理すること。
レビュー本体を specialized agent に任せる場合でも、このスキルは最後の出口整理として使う。

## 前提

- [AGENTS.md](../../AGENTS.md) の検証と報告の基準を前提に適用する。
- 変更内容と検証結果が確認できることを前提にする。

## 目的

- 変更後の自己レビューを標準化する。
- 指摘がある場合は findings-first で返し、ない場合も残リスクを明示する。

## 対象

- 実装後の最終確認。
- 複数ファイル変更や境界変更を含む差分。
- 変更内容をユーザーへ返す前の品質整理。
- `review-quality` / `review-security` agent の結果を、人間向けの出口整理へ統合する場面。

## 対象外

- 実装前の設計レビュー。
- ドキュメントだけの軽微更新で、レビュー判断が不要な依頼。

## 基本方針

- まず自己レビューする。
- 問題があれば findings-first で返す。
- 問題がなくても、未検証事項や残リスクは隠さない。
- 品質レビュー本体は `review-quality` agent、セキュリティレビュー本体は `review-security` agent を優先する。
- このスキルは specialized review の代替ではなく、レビュー結果を人間向けに整理して返す役割に徹する。

## 進め方

### 1) 事前条件をそろえる

- 次の 5 点を確認してからレビューに入る。
  - 差分またはレビュー対象の境界
  - 実施済みの検証
  - 未検証事項
  - 今回レビューしない範囲
  - specialized agent の結果有無
- specialized agent の結果がある場合は、その findings / open questions / residual risks を先に集める。
- 差分境界が曖昧な場合は、推測で全体レビューへ広げない。
- 検証結果がない場合は、レビュー不能ではなく `未検証` として明示する。
- `今回レビューしない範囲` がある場合は、最初に切り分けておく。

### 2) まず自己レビューする

- 次の観点を、出口整理に必要な範囲で短く確認する。
  - findings の根拠
  - open_questions と residual_risks の切り分け
  - 実施済み検証と未検証事項
  - 境界/影響範囲のうち、summary に残すべきもの
- 単一ファイルの軽微変更で、上記観点に強い懸念がなければ自己レビューのみで止めてよい。
- specialized agent の結果がある場合は、ここでは再レビューよりも重複除去と出口整理を優先する。

### 2.5) 観点漏れ防止の短いチェックリスト

- 品質では次を必要な範囲で確認する。
  - 変更意図と実装結果が食い違っていないか
  - 責務の混在、命名の不整合、例外処理の抜けがないか
  - 既存パターンから外れた書き方が、必要性なく持ち込まれていないか
- セキュリティでは次を必要な範囲で確認する。
  - 外部入力、秘密情報、権限境界、外部 I/O の扱いに不自然な点がないか
  - テンプレート値、サンプル文字列、ダミー値を根拠なく findings にしていないか
- テスト/検証では次を必要な範囲で確認する。
  - 変更に近い確認が実施済みか
  - 実施していない確認が結論に影響するか
- 境界/影響範囲では次を必要な範囲で確認する。
  - 公開インターフェース、永続化、認証認可、運用前提に影響が及んでいないか
  - 今回見ていない近傍領域を、残リスクとして分離すべきか

### 3) 出力を findings-first でまとめる

- 指摘がある場合:
  - `critical` / `high` / `medium` / `low` の順で findings を並べる
  - その後に open questions と residual risks を分けて添える
- 指摘がない場合:
  - `重大な指摘なし` を明示する
  - 何を確認してその結論に至ったかを短く添える
  - 実施済み検証、未検証事項、残リスクがあれば続ける
- `重大な指摘なし` は、reviewed scope に根拠のある `critical` / `high` がない場合に使う。
- `medium` / `low` だけが残る場合は、必要に応じて改善候補がある旨を添えてよい。
- 推測だけの懸念は findings にせず、`open_questions` または `residual_risks` に落とす
- `findings` は、差分または近傍コンテキストから根拠を示せるものだけに限る
- `open_questions` は、判断材料不足や意図未確認の論点に使う
- `residual_risks` は、未検証事項、運用前提依存、今回レビュー範囲外だが影響しうる論点に使う

## 出力ガイド

- レビュー結果には次を短く含める。
  - 対象差分または対象範囲
  - 実施済み検証
  - 今回レビューしなかった範囲
  - findings または `重大な指摘なし`
  - open questions
  - residual risks
- 固定閾値で機械的に判定しない。既存規約や近傍実装に照らして重み付けする。
