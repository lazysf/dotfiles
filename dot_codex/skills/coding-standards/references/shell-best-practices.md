# Shell Best Practices

`Shell`、`zsh`、`bash` で quoting、`return` / `exit`、シェル差異に迷うときの判断補助。

## エラー処理と終了コード

- `set -euo pipefail` は既存前提と整合する場合だけ使い、局所修正で流儀を変えない。
- 明示的に失敗を返す箇所は `return` と `exit` の責務を混ぜない。
- 失敗メッセージは、どのコマンドが何に失敗したか分かる粒度で出す。
- 期待される非 0 終了を握りつぶす場合は、理由が読める形にする。

## 変数と展開の目安

- パス、ユーザー入力、ワイルドカードが混ざる値は基本的に引用する。
- `[` と `test` より、既存が許すなら `[[` を優先して条件式の誤解を減らす。
- コマンド置換やパイプを増やしすぎず、1 回で済む外部呼び出しはまとめる。

## 設定と環境依存の扱い

- シェル固有機能は、そのファイルが依存できるシェルに閉じる。
- `PATH` や外部コマンド存在確認は、境界でまとめて扱う。
- ホスト依存や OS 分岐は、既存の条件分岐パターンへ寄せる。
- 関数名やローカル変数名は、対象ファイルのシェル流儀に合わせる。

## 避けたいこと

- 無引用の変数展開でパスや入力を壊すこと
- `return` すべき関数内で `exit` して呼び出し元まで巻き込むこと
- 単純な処理のために不要なサブシェルやパイプを増やすこと
