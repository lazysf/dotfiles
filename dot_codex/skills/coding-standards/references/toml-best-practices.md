# TOML Best Practices

`TOML` のテーブル配置、値表現、コメント運用に迷うときの判断補助。

## キーとテーブル構成の目安

- 既存のセクション順やまとまりを崩さず、近い設定のそばへ足す。
- 新しいネストは、本当に責務が増えるときだけ導入する。
- 同じ意味の値が複数候補に置ける場合は、近傍実装で採用済みの場所に揃える。

## 値の表現

- 真偽値、数値、配列は、既存と同じ表現を優先する。
- 複数行文字列やインラインテーブルは、読みやすさが明確に上がるときだけ使う。
- パスやコマンド文字列は、実際の解釈側が期待する形式に合わせる。

## コメントの目安

- 意味が自明なキーには説明コメントを足しすぎない。
- 外部制約や運用上の注意がある設定だけ、短く理由を書く。
- コメント追加で既存の視認性を落とすなら、まず配置で解決できるか考える。

## 変更時の注意

- 小さな追加で全体の並び替えや整形を広げない。
- 同時に複数セクションへ触る場合は、今回の依頼に必要な変更だけに留める。
- フォーマッタや自動整形前提のファイルかどうかを確認してから触る。

## 避けたいこと

- 値追加のついでに無関係なセクション順を入れ替えること
- 意味の薄いコメントを増やして、設定の見通しを悪くすること
- 解釈側の仕様未確認のまま、表現形式だけを好みで変えること
