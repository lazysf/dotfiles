# Knowledge Placement Rules

- 個人の作業メモや一時的な調査メモは、チーム共有の docs と混ぜない
- チームやプロジェクトで再利用する知識だけを共有対象にする
- 通常知見の蓄積先は `root docs/knowledge/` とする
- 通常知見の文面化には `core-write-knowledge-note` を使う
- 選択理由や却下した代替案ごと残す判断記録は `root docs/adr/` に置く
- 判断記録の文面化には `core-write-adr` を使う
- すでにコード、コメント、設定、成果物で十分に伝わる内容は追加しない
- docs を追加する場合は既存構造に寄せる
- 置き場が曖昧でもトップレベルに新しい運用ファイルを増やさない

共有候補になりやすいもの:

- API 変更や互換性の判断
- 運用手順の変更
- 以後も参照する設計判断
- 再発しやすい落とし穴や確認ポイント
- 複数案からの選定理由や採用 / 不採用の決定
