# 文書更新

既存のドキュメントを、実装事実と運用前提に沿って更新する。

## 手順

- 何が変わったかを整理し、影響する既存 docs を特定する。
- コード、設定、実行結果などの一次情報を根拠にする。
- 新規追加より、既存の自然な位置への差し込みを優先する。
- 既存の章構成、用語、粒度、文体に寄せ、今回必要な最小差分に留める。
- 前提条件、手順、期待結果、注意点のうち必要なものだけを書く。
- リンク、path、command、用語、他文書との整合を確認する。

## 境界

- 実装や設定で確認できない内容は、事実として書かない。
- 未確認事項は断定せず、確認待ちとして分ける。
- 小さな変更に合わせて文書全体を書き直さない。
- 知識をどこへ残すべきかの判断、`CONTEXT.md` 更新、新しい note / ADR 作成、ADR lifecycle metadata 更新は `planning` スキルを使う。
- docs review 専用依頼では、この skill だけで本文更新へ進まない。

## 出力

- どの文書を更新したかを短く示す
- 何を根拠に反映したかを示す
- 未確認事項や未実行の確認があれば隠さず示す
