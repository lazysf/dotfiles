# Docs Update

既存のドキュメントを、実装事実と運用前提に沿って更新する。
この skill は既存ドキュメントの更新に責務を絞り、知識の置き場判断は `capture-knowledge-triage` に委ねる。

## 対象

- README
- セットアップや運用手順
- 設計メモや開発ガイド
- 既存 docs の説明修正や追記

## 対象外

- 知識をどこへ残すべきかの判断
- 新しい通常知見メモや ADR の草案作成
- ADR の `Status`、`Supersedes`、`Superseded-By` などの lifecycle metadata 更新
- ドキュメントのレビュー専用依頼

## 基本方針

- コード、設定、実行結果などの一次情報を根拠にする。
- 既存の章構成、用語、粒度、文体に寄せる。
- 今回の変更に必要な最小差分に留める。
- 未確認事項は断定せず、確認待ちとして分ける。
- リンク、パス、コマンド、参照関係は可能な範囲で確認する。

## 手順

1. 何が変わったかを整理し、影響する既存ドキュメントを特定する
2. 新規追加より、既存の自然な位置への差し込みを優先する
3. 前提条件、手順、期待結果、注意点のうち必要なものだけを書く
4. リンク、パス、コマンド、用語、他文書との整合を確認する
5. 更新した内容、確認できたこと、未確認事項を分けて残す

## 判断基準

- 実装や設定で確認できない内容は、事実として書かない
- 小さな変更に合わせて文書全体を書き直さない
- docs-only の更新と、知識の置き場判断を混ぜない
- 読者が次に何をすればよいかで迷わない形を優先する

## 出力ガイド

- どの文書を更新したかを短く示す
- 何を根拠に反映したかを示す
- 未確認事項や未実行の確認があれば隠さず示す
