# Environment Audit

Codex 環境の整合性確認に専念する、読み取り専用スキル。
目的は、`config / AGENTS / docs / skills / rules / agents` の状態を点検し、どこを直すべきかを事実ベースで整理すること。

## 前提

- [AGENTS.md](../../AGENTS.md) の共通品質原則を前提に適用する。
- 実装や修正そのものではなく、環境点検を主目的とする。

## 目的

- Codex の設定、文書、rules、skills、agents の整合性を確認する。
- 重複、抜け、導線不整合、運用上の詰まりを洗い出す。
- 修正実行の前段として、改善候補を短く整理する。

## 対象

- `~/.codex` 相当の運用環境を見直したい相談。
- `AGENTS.md`、skills、rules、docs の導線を点検したい相談。
- 「どこを整備すると使いやすくなるか」を洗い出したい相談。

## 対象外

- リポジトリ固有機能の実装や不具合修正。
- 実際の設定変更やファイル編集そのもの。
- `workspace-intake` が扱う、通常の実装対象探索。

## 点検観点

### 1) 役割の整合性

- `AGENTS.md`、README、実務ガイド、skills の責務が重複していないか確認する。
- 同じことを複数箇所で説明していないか確認する。

### 2) 導線の分かりやすさ

- 依頼の入口、長い作業の進め方、レビュー、環境点検の導線が見えるか確認する。
- 読み始める順番が自然か確認する。

### 3) ガードレールの妥当性

- rules の禁止・許可・要確認が意図どおりに分かれているか確認する。
- 危険操作や権限操作の扱いに曖昧さがないか確認する。

### 4) 運用上の詰まり

- 想定される日常フローで詰まりやすい点がないか確認する。
- 実行不能や未検証のポイントがあれば、その前提を明示する。

## 使い分け

- 通常の実装探索は `workspace-intake` を使う。
- 依頼の整形は `request-shaping` や `task-intake` を使う。
- 環境そのものの見直しは、この `environment-audit` を使う。

## 出力ガイド

- 出力は次の項目に固定する。
  - 依頼要約
  - 確認した事実
  - 問題点
  - 推奨変更
  - 未確認事項
- 推測は断定せず、事実と分けて扱う。
- 修正案は出してよいが、その場で実装したことにしない。
