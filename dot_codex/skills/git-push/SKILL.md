# Git Push

## 概要

現在のブランチのローカルコミットをリモートへプッシュし、必要ならupstreamを設定する。タグのプッシュは明示要求がある場合のみ行う。失敗や曖昧な指示は止めて確認する。
プッシュは安全性を優先しつつ、単一の upstream が明確ならそれを既定として扱う。

## 対象外

- コミット作成やコミットメッセージ整備のみが目的の依頼（git-commit を使用）。
- プル/リベースで履歴調整が必要だが、調整指示がない状態。
- 強制プッシュの実行（現行ルールでは `git push --force` / `--force-with-lease` を許可しない）。

## 手順

### 1) 状況確認

- 現在のブランチとupstreamの有無を確認:
  - `git status -sb`
  - `git branch -vv`
- リモート一覧を確認:
  - `git remote -v`
- 単一の upstream が明確でない状態で複数リモートがある場合は、プッシュ先を確認し、確認が取れるまで停止する。
- detached HEADなら止めて、どのブランチへプッシュするか確認する。
- rebase・merge・cherry-pick・revert 中やコンフリクトがある場合は止めて確認する。
- 未コミットの変更はプッシュ対象外である旨を必要に応じて伝える。
- 保護ブランチ運用（main/master への直接 push 制限など）が既知なら、規約を優先する。

### 2) プッシュ対象の判定

- `git status -sb` で ahead が 0 かつタグのプッシュ指示がない場合は「プッシュ対象がない」旨を伝えて終了する。
- ahead が 0 でもタグのプッシュ指示がある場合は、タグのみ実行する。
- タグのみ実行の場合は、ブランチのプッシュ（手順4）を省略して手順5へ進む。
- behind または diverged と表示された場合は、プル・リベースの要否を確認し、指示があるまでプッシュは中止する。
- upstream が設定されているが、現在のブランチ名と一致しない場合は確認する。

### 3) プッシュ先の決定

- ユーザーがリモート名やブランチ名を明示した場合は、それを最優先する。
- upstream が設定されていて push 先が一意なら、その upstream を既定として使う。
- upstream が未設定で、`origin` が存在し単一リモートなら `origin` と現在のブランチを既定として使う。
- upstream が未設定で複数リモートがある場合は確認する。
- ユーザーがリモート名やブランチ名を明示した場合は、常に明示指定を優先し `git push <remote> <branch>` 形式で実行する。
- upstream が既にあり、明示指定と異なる場合は実行前に確認する。

### 4) プッシュ実行（強制は使わない）

- upstreamが未設定で既定先が決められているなら:
  - `git push -u <remote> <branch>`
- upstreamが既にある & 明示指定がないなら:
  - `git push`
- upstreamが既にあるが明示指定があるなら:
  - `git push <remote> <branch>`
- 高リスク操作（強制プッシュ・タグ大量送信）の前は、必要に応じて `--dry-run` を提案する。

### 5) タグのプッシュ（明示指示がある場合のみ）

- すべてのタグをプッシュ:
  - タグ数が多い場合は確認する。
  - リモート指定がある場合: `git push <remote> --tags`
  - リモート指定がない場合: `git push --tags`
- 特定タグのみプッシュ:
  - タグが存在しない場合は止めて確認する。
  - `git push <remote> <tag>`

### 6) 強制プッシュ（対象外）

- 強制プッシュは現行ルールセットでは禁止されているため、明示依頼があっても自動実行しない。
- 必要性がある場合は、通常 push で解決できない理由を確認し、別途運用判断に委ねる。

### 7) 失敗時の扱い

- 認証エラー、non-fast-forward、保護ブランチなどのエラーは止めてユーザーに確認する。
- 自動で解決策を実行しない（ユーザーの指示があれば対応）。
- エラー種別ごとに次アクションを分ける（認証: 権限確認、non-fast-forward: 同期方針確認、保護ブランチ: 運用手順確認）。

## 出力フォーマット

```markdown
# Push結果

- remote:
- branch:
- upstream設定:
- 実行内容: 通常push / tag push
- 結果: 成功 / 失敗
- 失敗時の次アクション:
```

## 例

- 「プッシュ」
  - 単一 upstream があればそこへプッシュ。upstream未設定で単一リモートなら `-u` を使う。
- 「今のコミットをプッシュして」
  - 上と同様。
- 「タグもプッシュして」
  - ブランチをプッシュ後にタグをプッシュ。
- 「タグだけプッシュして」
  - ブランチはプッシュせず、タグのみプッシュ。
## 返答のガイド

- どのリモート・ブランチへプッシュしたかを簡潔に報告する。
- upstream を設定した場合はその旨を明記する。
- タグをプッシュした場合はタグの種類（全タグ・特定タグ）を明記する。
- 強制プッシュ依頼を受けたが対象外だった場合は、その旨と停止理由を短く示す。
- 失敗時はエラー種別と次アクションを短く示す。
