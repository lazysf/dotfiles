# Requirements Heuristics

要件整理の迷いどころだけを扱う補助資料。
ここに書く内容は必須ルールではなく、迷ったときの目安。

## まず疑うこと

- 依頼者が本当に困っているのは何か。
- その要求は手段であって、目的ではないか。
- 今回やらないことが曖昧なまま膨らんでいないか。
- 成功条件が「なんとなく良くなる」になっていないか。

## 整理したい項目

- 背景
- 課題
- 期待結果
- 非目的
- 制約
- 優先順位
- 未確定事項

## 確認を先に置くべき場面

- 複数の解決方向がありそう。
- ユーザーごとに期待結果が違いそう。
- 互換性や運用制約でスコープが大きく変わる。
- 実装前に合意しないと手戻りが大きい。

## 避けたい兆候

- 目的より先に UI や実装方式を決めている。
- 非目的がなく、際限なく広がる。
- 必須と任意が分かれていない。
- 未確定事項を隠したまま技術計画へ進んでいる。
- 実装タスクの箇条書きが、そのまま要件の代わりになっている。
