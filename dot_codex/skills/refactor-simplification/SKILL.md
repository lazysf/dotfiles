# Refactor Simplification

過剰実装や複雑な処理を、既存挙動を守ったまま読みやすく単純な形へ整理する。
単純化したい対象が見えている時に、最小で切り戻しやすい計画を置く。

## 対象

- 過剰な分岐、設定、抽象化、汎用化、helper、層分けを減らしたい依頼
- 重複や責務の分散により、意図が追いにくくなった実装を整理したい依頼
- 既存挙動を変えず、今必要な処理だけが残る形へ寄せたい依頼

## 対象外

- リファクタ境界そのものを広く決める依頼
- 性能、安定性、可用性、可観測性、運用性の改善を主目的にする依頼
- 公開 API、永続化、データ形式、権限、依存追加、設計刷新を主目的にする依頼
- 単独の bugfix、差分レビュー、実装作業そのもの

## 手順

1. 単純化したい対象を `simplification_target` に絞る
2. 複雑さの原因を `complexity_source` に整理する
3. 今回触らない範囲を `non_scope` に置く
4. 守るべき既存挙動を `protected_behavior` に並べる
5. 最小で切り戻しやすい整理方針を `simplification_plan` に置く
6. 同じ挙動を保てたことの確認方法を `verification_focus` に置く
7. 進めず確認すべき条件を `stop_conditions` に分ける

## 判断基準

- `可読性優先`、`KISS`、`YAGNI`、`DRY` の順で判断する
- 短さではなく、読み手が意図と責務を追いやすいことを優先する
- 将来のためだけの抽象化、設定、拡張ポイントは削る候補にする
- 重複は、実害があり、単純さを損なわずに解消できる場合だけまとめる
- 内部の dead code 候補や局所整理は、根拠と確認方法がある範囲で計画に含めてよい

## 出力フォーマット

- `simplification_target`
- `complexity_source`
- `non_scope`
- `protected_behavior`
- `simplification_plan`
- `verification_focus`
- `stop_conditions`

## 完了条件

- 削る対象、守る挙動、触らない範囲、最小変更方針、確認方法が揃っている
- 既存挙動を変えない前提が検証観点に結び付いている
- 実装に入る場合は `code-implementation-loop` スキルへ渡せる粒度になっている

## 停止条件

- 既存挙動の保護方法が見えない
- 公開インターフェース、永続化、データ形式、権限、秘密情報、本番設定に影響する
- 外部契約や既存挙動に影響する削除、統合、公開面変更が必要になる
