# Request Shaping Templates

`request-shaping` で迷ったときの補助資料。
ここでは、依頼を短い実装ブリーフへ整えるための型だけを扱う。

注意:

- これはユーザーへの必須入力テンプレートではない。
- 会話から補えるものは補い、結果を左右する未確定事項だけを残す。

## 基本テンプレート

```markdown
## 目的

- [今回の主題を一文で]

## 確認済み事実

- [確認済みの事実]

## 制約

- [触ってよい範囲、避けたい変更、期限、互換性]

## 仮定

- [会話から暫定補完した前提]

## 未確定事項

- [高リスクな不明点]

## 次アクション

- [次に task-intake で固めること]
```

## 良い整形の例

- 要望が複数あっても、今回の主題は 1 つに縮める。
- 「多分」「おそらく」は事実欄へ置かず、仮定や未確定事項へ送る。
- 今すぐ決めなくてよいものは未確定事項へ残し、次アクションへ回す。

## 避けたい整形

- 技術解を先に決め打ちして、目的が見えなくなる。
- 背景説明だけ長く、主題や次アクションが空になる。
- 不明点を埋めずに断定口調で次工程へ渡す。
