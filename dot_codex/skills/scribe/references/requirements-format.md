# Requirements Format

`requirements.md` は要件フェーズの正本であり、Gate 1 のレビュー対象。

## Rules

- `REQ-*` は実現したい振る舞いとして書く。
- `AC-*` は観測可能な受入条件として書く。
- `AC-*` は対応する `REQ-*` を含める。
- 実装方法、基本設計、詳細設計、task、実装結果を書かない。
- 制約、前提、未確認事項を分ける。

## Template

```markdown
# Requirements

## 目的

[何を達成したいか。]

## 背景 / 課題

[なぜ必要か、何に困っているか。]

## Scope

- [今回実現すること。]

## Non-Scope

- [今回やらないこと。]

## 要求事項

- `REQ-001`: [実現したい振る舞い。]

## 受入条件

- `AC-001`: [観測可能な受入条件。対応する `REQ-*` を含める。]

## 制約

- [技術、運用、互換性、権限、期限などの制約。]

## 前提

- [既に確認済みで、設計の土台にしてよいこと。]

## 未確認事項

- [設計前、または設計中に追加調査すべきこと。]
```
