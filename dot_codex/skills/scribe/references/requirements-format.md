# Requirements Format

`docs/REQUIREMENTS.md` を作成・更新する時に使う。
`FR-*` ごとに、実現したい振る舞いと受入条件を扱える粒度まで固める。

## Rules

- 要件用フォルダは作らず、`docs/REQUIREMENTS.md` を使う。
- 機能または要件領域は `FR-001`、具体要求は `REQ-001`、受入条件は `AC-001` のような ID で追跡する。
- 既存 ID があれば継続する。
- ID 体系が未確定なら、推測で採番せず確認する。
- 受入条件は観測可能な結果として書く。
- 未確認事項は `未確認事項` に残す。

## Template

```markdown
# 要件定義

## FR-001: [機能または要件領域名]

### 背景

[この要件が必要な確認済み背景。]

### 要求事項

- `REQ-001`: [実現したい振る舞い。]

### 受入条件

- `AC-001`: [観測可能な受入条件。]

### 非目的

- [この要件では扱わないこと。]

### 前提・制約

- 前提: [依存する要件、外部条件、既存仕様。]
- 制約: [互換性、運用、policy、UX、data、rollout など。]

### 未確認事項

- [未確認事項。]
```
