# TODO 形式

保留の作業を `TODO.md` などの doc に書く時に読む。保留の作業を doc と issue のどちらに置くかは、repo の運用に従う。issue で管理している repo では、この reference を使わない。

## 置き場と命名

repo が決めた置き場（`AGENTS.md` や `DEVELOPMENT.md` に書かれた先）に書く。決まっていなければ、作る前にユーザーに聞く。issue も使う repo に `TODO.md` を作ると、保留の作業が二重になる。

## 構成

既存の TODO が章立てや項目の形を持っていれば、それに合わせる。無い時は次の形にする。項目は GitHub の task list（`- [ ]`）で書く。

```markdown
# TODO

- [ ] **[何をするか]**
  - 記載: YYYY-MM-DD（[見つけた時の作業]）
  - 完了の条件: [何を確かめたら閉じるか]
  - 関連: [notes、issue、commit への指し先]
```

- 関連は、指す先がある時だけ書く。
- 項目が増えたら、題ごとの章（`## [題]`）にまとめてよい。

## 書く規則

- 記載日と、見つけた時の作業を書く。後で読む人が、いつ何をしていて見つけたかを追える。
- 完了の条件を書く。条件が無いと、後で閉じてよいかを決められない。
- 調べた結果の詳細は書かない。notes に置き、TODO には指し先だけを残す。notes に置けば、項目を閉じた後も今の設計の理由として残る。
- 今の作業で直すものは、TODO に移さない。

## 更新と退役

完了した項目を消すか、`[x]` を付けて残すかは、既存の TODO の形に従う。
