# docs/ の利用者向け doc 形式

`docs/` 配下に、利用者向けの詳しい doc（使い方、設定の一覧、概念の説明）を作成・更新する時に読む。`docs/README.md`、ADR、notes はそれぞれの reference を読む。

## 1 つの doc に 1 つの種類

書く前に、doc の種類を次の 3 つから 1 つ選ぶ。3 つは [Diátaxis](https://diataxis.fr/start-here/) の how-to、reference、explanation に当たる。

| 種類 | 読み手が求めるもの | 書くもの |
| --- | --- | --- |
| how-to | ある目的を達する手順 | 前提、手順、結果の確かめ方 |
| reference | 正確な一覧 | 設定キー、コマンド、引数、既定値 |
| explanation | なぜその形かの理解 | 概念、仕組み、制約 |

- 1 つの doc に 2 つの種類を混ぜない。手順の途中に概念の説明を挟むと、手順を引きたい読み手が迷う。
- 他の種類の内容が要る時は、その種類の doc へリンクする。
- 既存の `docs/` が別の分け方をしていれば、そちらに従う。

## 種類ごとの規則

- how-to の手順は、読み手の環境で、書いた形のまま一度通す。外へ出る操作（公開、配布、課金）は通さず、定義と突き合わせるだけにする。
- reference は、実体の定義（schema、`--help` の出力、設定ファイル、型の定義）と突き合わせる。どの定義と突き合わせたかを doc に書く。定義と doc が食い違ったら、定義を正とする。
- explanation には、利用者の判断に効く理由だけを書く。開発の経緯と判断の比較は ADR や notes に置く。

## README との分担

- README には、導入と最小の使い方を残す。詳しい手順と一覧は `docs/` に置き、README から指す。
- 同じ手順を README と `docs/` の両方に書かない。片方だけ古くなる。
- `docs/` に doc を足したら、`docs/README.md` の案内と、README からのリンクを確かめる。
