# Session Orchestrator

高品質なバイブコーディングのための、長めの作業向け進行管理スキル。
目的は、探索から変更レビューまでの切り替え条件をそろえ、長いセッションでも迷わず進めること。

## 前提

- [AGENTS.md](../../AGENTS.md) の共通品質原則、既定フロー、確認必須境界を前提に適用する。
- `workspace-intake` により、関連する規約や近傍実装がある程度見えていることを想定する。

## 目的

- 長めの変更を、小さな進行単位に分ける。
- いつ探索を終え、いつ要件整理へ進み、いつ実装へ入るかを明確にする。
- 途中確認ポイントと終了条件を先に置く。
- 必要な場面では、同一スレッド内で文脈を圧縮する checkpoint を置く。
- 長い作業でも `1 task = 1 thread` を保ち、必要なときだけ fork や compact を使えるようにする。

## 対象

- 複数ファイルや複数段階にまたがる変更。
- 途中で相談や確認を挟みながら進めたい作業。
- `plan-product` と `plan-architect` の前後で、進め方を整理したい依頼。

## 対象外

- 単純な一発修正。
- 技術設計そのものを詳細に詰める依頼。

## 基本方針

- まず現在地を確認し、次の最小スライスだけを明確にする。
- フェーズを増やしすぎず、探索、要件整理、実装、検証、変更レビューの5段階で扱う。
- 各段階に `次へ進んでよい条件` を付ける。
- 実装内容そのものの設計判断は `plan-architect` に委ねる。
- 長い作業で文脈が膨らんだら、別スレッドではなく同一スレッド内の checkpoint で圧縮する。
- 別スレッドへの fork は、本当に別問題へ分岐したときだけ使う。
- 会話が長くなりすぎたら、checkpoint を置いたうえで compact を検討する。

## 切り替えの考え方

### 1) 探索から要件整理へ進む条件

- 関連規約、近傍実装、確認手段が見えている。
- まだ要件が揺れるなら `plan-product` へ渡す。

### 2) 要件整理から実装準備へ進む条件

- 目的、完了条件、非目的、制約が説明できる。
- 実装順序の整理が必要なら `plan-architect` へ渡す。

### 3) 実装へ進む条件

- 次の最小スライスと書き込み範囲が定まっている。
- 高リスクな不明点が残る場合は、実装前に確認を置く。

### 4) 検証へ進む条件

- 実装差分が最小単位でまとまっている。
- 何を確認すれば今回の変更が前進したと言えるかが分かる。

### 5) 変更レビューで終える条件

- 実行できた検証と未検証事項が分かれている。
- 残リスクと次の確認事項が短く説明できる。

### 6) Checkpoint を置く条件

- 長い作業で、確認済み事実や決定事項が会話中に散らばってきた。
- このまま進めると、次の最小ステップが見えにくい。
- 同一スレッドのまま、ここまでの文脈を圧縮して残したい。

### 7) Fork / Compact を使う条件

- fork:
  - 元の問題と独立した別タスクへ分岐したときだけ使う。
  - 同じ問題の続きなら、同一スレッドを維持する。
- compact:
  - 会話が長くなり、過去の決定事項が参照しづらくなったときに使う。
  - compact 前に checkpoint を置き、重要な事実と決定事項を明示してから圧縮する。

## 後続との使い分け

- 要件整理が必要なら `plan-product`
- 技術計画が必要なら `plan-architect`
- 実装は `coding-standards`
- 検証は `test-runner`
- 出口整理は `change-review`
- 環境そのものの点検は `environment-audit`

## 出力ガイド

- 出力は次の項目に固定する。
  - 現在地
  - 次の最小スライス
  - 途中確認ポイント
  - 検証方法
  - 終了条件
- 必要なら thread 運用メモとして `checkpoint / fork / compact の判断` を添えてよい。
- 必要なら checkpoint として次を追加する。
  - 目的
  - 確認済み事実
  - 決定事項
  - 未決事項
  - 残タスク
  - 検証済み・未検証
  - 次の最小ステップ
- 詳細な進行テンプレートが必要なら [references/session-orchestrator-templates.md](references/session-orchestrator-templates.md) を参照する。
