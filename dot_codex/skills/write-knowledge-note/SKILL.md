# Write Knowledge Note

通常知見として残す内容を、`root docs/knowledge/` 向けの短い知見メモ草案へ整理する。
この skill は文面作成に責務を限定し、ファイル作成や既存文書更新の実行は行わない。

## 基本方針

- 通常知見として残す理由を先に明確にする。
- 判断記録ではなく、共有して再利用したい知見だけを扱う。
- 草案は短く、後から参照しやすい形に絞る。
- 内容に応じて要点を優先し、重い固定構造を持ち込まない。

## 対象

- 手順メモ
- 確認ポイント
- 再発しやすい落とし穴
- 軽量な運用メモ
- 再発防止メモ

## 対象外

- 複数案からの選定理由を残す判断記録
- 方針変更や互換性判断
- 採用 / 不採用の決定
- 上記に当てはまる内容は `write-adr` を使う

## 出力ガイド

- 想定ファイル名案は `docs/knowledge/kebab-case-title.md` の形式で示す。
- 知見メモ草案は短い Markdown で返す。
- 必須の固定見出しは `# Title` のみとし、必要なら要点や注意点を簡潔に加える。

## 手順

### 1) 通常知見として残す理由を整理する

- 何を覚えておくべきかを一文でまとめる。
- なぜ判断記録ではなく通常知見として残すのかを確認する。

### 2) 要点をそろえる

- 手順、確認ポイント、注意点のうち必要なものだけを抜き出す。
- 背景説明は、知見を理解するのに必要な範囲へ絞る。

### 3) ファイル名案を作る

- 内容を表す短い kebab-case のタイトルを付ける。
- ファイル名案は `docs/knowledge/kebab-case-title.md` として返す。

### 4) 知見メモ草案を書く

- `# Title` を置く。
- 本文は短い知見メモとして、要点中心にまとめる。

## 完了条件

- 通常知見として残す理由が説明できる
- `docs/knowledge/kebab-case-title.md` 形式のファイル名案がある
- 短い Markdown 草案がある
